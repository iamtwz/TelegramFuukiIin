# 管理说明

私聊 Bot 发送 `/admin`。后台仅管理 `MANAGED_CHAT_IDS` 中的群，界面与通知使用中文。

## 权限与命令

每次查询或操作都通过 Telegram 检查当前权限；群名缓存 5 分钟，不缓存操作授权。`SUPER_ADMIN_IDS` 仅增加全部已配置群的查看权限，修改设置或处罚仍需要该群的实际权限。普通用户看不到管理菜单，手输命令也不能获得访问权限。审核和故障通知只发给获授权者的私聊；管理员须先发送 `/start`。

| 命令 | 用途 |
| --- | --- |
| `/admin [群ID]` | 群列表和设置 |
| `/pending 群ID` | 待审案件 |
| `/case 群ID 案件ID` | 消息/资料快照与处理状态 |
| `/audit 群ID` | 按类型筛选审计，分页查看原消息快照 |
| `/stats 群ID [YYYY-MM-DD]` | 每日统计及近 7/30 天汇总 |
| `/health 群ID` | Bot 权限和任务状态 |
| `/thresholds 群ID 60 80` | 人工/自动封禁阈值 |
| `/retry 群ID` | 重试 7 天内失败的任务 |
| `/unban 群ID 用户ID` | 解除封禁并取消相关未完成处罚 |

放行/封禁需要删除消息和限制成员权限，入群资料审核另需邀请权限；设置、重试和解封需要三项权限，群主可执行。普通用户可使用 `/ping`、`/whoami`、`/version` 和私聊 `/help`。

Bot 回复使用 MarkdownV2 排版，ID、用户名、命令和数值以等宽字体显示，证据 JSON 使用代码块。`/ping` 仅回复 `Pong! 🏓`；其他普通用户回复保持中英双语。按钮和命令菜单使用普通文本。

`/version` 查看当前运行的 Bot 版本，管理面板和 `/health` 也显示版本号。程序的 `--version`、启动日志及 HTTP 请求标识使用相同的构建版本；发布版本以根目录 `Cargo.toml` 的 `workspace.package.version` 为准。

## 检测规则

| 模式 | 检测范围 |
| --- | --- |
| 入群首条（默认） | Bot 观察到入群后，该用户本次入群的首条内容消息 |
| 首次发言 | 该用户在此群首次被 Bot 记录的内容消息，包括未入群评论者 |

首次发言标记按群和用户保存，跨帖子/话题共用，重启或模式切换不会清空。关闭检测期间仍维护标记，重新开启不追溯；已有案件继续处理。后续普通消息、编辑消息不检测，相册仅第一项消耗首条机会；服务消息、自动转发、匿名/频道身份不占个人首条机会。媒体不做 OCR 或转录。

送审包括消息、按钮、昵称、用户名及可获取的 BIO/链接/mentions。读取不到的资料标为未知，不访问这些链接，也不把 BIO 中提及的人当作处罚对象。

Guest Bot 回复逐条审核，独立于首条标记。仅依据 Telegram 官方召唤者字段归责；高风险时删除回复并封禁 Bot，另处理明确识别的个人召唤者及可确认的召唤消息。普通 inline Bot 消息只处罚实际发送用户。管理员受到保护，缺少个人召唤者信息时不猜测身份。

默认 ≥80% 自动删除封禁，60%–<80% 转人工，低于 60% 放行。中风险消息在审批前仍可见，模型故障重试后转人工；删除与封禁分别记录进度。阈值调整只影响新案件，删除的消息不能恢复。

默认入群只做验证码，不调用 Jev。面板可开启“入群资料审核（Jev）”；开启后资料审核和验证码须同时通过。关闭验证码不会自动批准申请。

## 统计口径

日期按 UTC+8，保留 365 个自然日。申请人数按群/用户/日去重；通过率为 Bot 完成批准或确认已入群的人数除以该日申请人数，跨日批准回填申请日。多日汇总为每日去重人数之和。

消息量按案件计数，重复更新/重试不增加条数。Spam 率为达到案件封禁阈值的条数除以成功分类条数，不代表实际封禁成功率；入群资料审核单独统计。Tokens 和费用使用接口返回值，缺失显示未知，每次真实调用（含重试）独立计量。数据从该群开始采集时计算，不推算未观察到的历史行为。

## 日志与排错

设置 `LOG_LEVEL=verbose` 查看更新摘要、调用耗时、任务结果和 `screening.skip` 跳过原因；`debug` 另含脱敏输入输出及消息正文。修改配置后重新创建容器，完成排查后恢复 `info`。日志写入 stderr，Compose 自动轮转。

| 现象 | 检查方向 |
| --- | --- |
| 没有审核 | 群白名单、检测模式、首条是否已记录；按消息 ID 查 `telegram.update`、`screening.skip` 和 `audit` |
| `not_first_message` | 普通用户首条机会已消费 |
| `no_active_join_observed` | 入群模式没有观察到入群；讨论群可改用首次发言 |
| `guest_message_already_screened` | 同一 Guest 消息重复交付，已有案件 |
| `invalid_or_stale_date` | 时间无效或超过 7 天窗口 |
| `telegram.clock_skew` | Telegram 时间领先本地超过 30 秒；普通消息继续审核，入群凭证仍严格校验时间 |
| 申请后无私聊 | 邀请权限、Bot 在线状态、申请私聊窗口、用户是否屏蔽 Bot |
| 验证失败或未批准 | 正式域名、Site Key/Secret 配对、网络、最新申请与会话有效期 |
| 删除/封禁只完成部分 | 检查权限及审计，修复后重试 |
| 持续 409 轮询错误 | 同一 Token 是否运行了多个实例 |

`job.complete` 只表示任务完成，不证明调用过模型。Debug 日志含个人内容，不受 SQLite 清理策略控制；分享前删除敏感内容。

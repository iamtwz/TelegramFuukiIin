# 隐私与数据处理

部署者应向群成员说明数据处理方式，并负责本地数据、日志和第三方账号。

## 数据流向

- **OpenRouter / Jev**：被检测消息的正文/Caption、按钮、可见元数据，以及发送者、Bot、可识别召唤者的 ID、昵称、用户名、可读取的 BIO 与其中的链接/mentions。单独入群资料审核默认关闭。
- **Cloudflare**：用户浏览器访问 Pages 和 Turnstile；Bot 向 Siteverify 提交验证码 token，不主动传递用户 IP。Pages URL 包含群 ID、随机会话 ID、公开 Site Key，不包含 Bot Token 或消息正文。
- **Telegram**：接收命令、验证码回传及管理操作。授权管理员和配置的超级管理员可在私聊查看案件证据；已发送的证据消息不会随本地数据库清理而删除。
- **本地 SQLite**：成员/首条标记、申请、案件、任务、审计、统计、群名缓存与管理菜单同步状态。
- **浏览器**：localStorage 仅保存语言选择；没有自建分析 SDK。

不下载媒体、不访问消息或 BIO 中的链接、不做 OCR/转录。第三方平台仍按各自政策处理请求和元数据。

## 数据保留

| 数据 | 保留 |
| --- | --- |
| 已结案证据 | 7 天 |
| 未结案证据 | 最多 30 天 |
| 案件元数据 | 37 天 |
| 验证会话 | 24 小时 |
| 已完成/失败任务及去重信息 | 7 天；完成任务立即清空 payload |
| 审计 | 30 天 |
| 每日统计元数据 | 365 个自然日 |
| 成员周期、首条标记、菜单同步、统计启用时间 | 长期保存以维持去重和授权展示 |

验证 token 仅为校验和重试短期保存，通过、过期或被替换后清理。数据库清理是逻辑删除，不保证 WAL、空闲页或备份中的物理擦除。

默认 `info` 不记录消息正文，`verbose` 含用户/群 ID 等元数据。`debug` 会记录个人内容，包括未送审消息；密钥和验证码脱敏不等于消息匿名化。日志独立于数据库保留策略，应限制访问并单独轮转、删除。

## 群公告示例

> 本群使用 Telegram 风纪委员进行入群人机验证和反垃圾审核。被检测消息、按钮及相关用户可见资料会通过 OpenRouter 交给 Jev 判断；高风险消息可能被删除并封禁，中风险由管理员审核。默认入群仅使用 Cloudflare Turnstile。误判请联系群管理员。
